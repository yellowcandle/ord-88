# Verify the Section 88 plate

The app is one static page, `dist/index.html`, plus `dist/data.json`, both generated by `python3 build_site.py` from the repo's CSVs. There is no JavaScript, no router, and no form: verifying means serving the built directory over HTTP, loading the real page in a browser, and checking that what a reader sees matches the data the build wrote. Unit tests (`tests/test_visualisation.py`) cover provenance relationships in the HTML source; this skill covers what the browser actually renders.

Feature recipes live in [`features/README.md`](features/README.md). Read it before driving.

## Launch

```bash
python3 build_site.py
```

Writes `dist/index.html`, `dist/data.json`, and refreshes `dist/fonts/`. A build that only warns about unclassified societies still succeeds; capture the warning text, it is part of the proof.

Serve the built directory (never `file://` — the `@font-face` files 404 there and the page renders in fallback fonts):

```bash
python3 -m http.server 8811 --directory dist
```

Start it as a named omp service so it stays observable and killable:

```bash
bash command: python3 -m http.server 8811 --directory dist  (name: plate-verify)
```

Ready means usable: `GET http://127.0.0.1:8811/index.html` returns 200 **and** the body contains `<main class="plate">`. Poll once via the doctor below; do not sleep.

Teardown is one call: `write proc://plate-verify/kill` with no content.

## Doctor

Run this first whenever anything looks off:

```bash
.omp/skills/verify-plate/scripts/doctor.sh 8811
```

It is read-only. It checks, in order: the port answers, the served document is the current `dist/index.html` (byte-identical), the page carries `<main class="plate">`, `dist/data.json` parses and has the aggregate keys, and it prints `git status --short dist` so you can see whether the build rewrote tracked files. Every line prints `ok` or a failure; nonzero exit means do not drive this instance.

## Drive

Use the omp browser prelude — no other harness exists in this repo.

```js
const tab = await browser.open({
  name: "plate",
  url: "http://127.0.0.1:8811/index.html",
  viewport: { width: 1440, height: 2600 },
});
await tab.waitForSelector("main.plate");
```

Stable handles, all from `build_site.py`'s template:

| Surface | Selector |
| --- | --- |
| Hero total | `.plate .hero` |
| As-at / source stamp | `.plate-head .meta`, `.source-line` |
| Stage 1 heading / bands | `#cap-stage1`, `.stage-col .band-row` (`.band-count`, `.band-share`) |
| Stage 2 heading / labels | `#cap-stage2`, `.trad-labels .trad-label` |
| Stage 3 heading / rows | `#cap-stage3`, `.denom-list li` |
| Ranked schedule | `table.schedule` rows `.sched-row` (`.rank`, `.name`, `.count`, `.share`) |
| Footer notes / imprint | `.note`, `.imprint` |

Read text with `tab.text(selector)` / `tab.$$eval`-style `tab.run` code; do not grep whole-body text — `.sr-only` lists repeat the same numbers and will make a substring check pass for the wrong reason.

To prove the page agrees with the build, compare against `dist/data.json` read from disk: hero equals `total` with thousands separators, `.sched-row` count equals `len(purposes)`, Stage 2 heading contains `religious_total`, Stage 3 heading contains `denomination_count` and `denomination_total`.

## Evidence

Write proof to `verify-artifacts/<run-id>/` in the repo root (`<run-id>` = ISO date + one-word change label). A proof is:

- `plate-full.png` — `tab.screenshot({ fullPage: true })`, the whole page as a reader sees it.
- `plate-stage2.png` — viewport screenshot of the Stage 2 chart, where the band geometry is the claim.
- `assertions.txt` — selector, expected value, observed value, per check, plus the exact build command and its stdout/stderr.
- `data.json` — a copy of the build output the assertions were compared against.
- `git-diff-dist.txt` — `git diff --stat dist/` (and `--numstat` if sizes move), because the build rewrites tracked files.

Standards: exercise the real page over HTTP, not the HTML file on disk. Capture the rendered state, not the source template. Never delete `verify-artifacts/` during cleanup. Verification artifacts are not git-ignored, so leave them out of commits.

## Cleanup

```bash
write proc://plate-verify/kill
```

Then close the tab: `browser.close({ name: "plate" })` (or `close({ all: true })` if you opened more). Never kill by process name and never reuse a server another run started. After teardown, confirm the evidence files still exist at the named path — cleanup that eats the proof fails the run.

The build itself is not reverted: it rewrites `dist/index.html`, `dist/data.json`, and `dist/fonts/`, which are tracked. Report the `git diff` and let the user decide whether to keep or commit the rebuild.
